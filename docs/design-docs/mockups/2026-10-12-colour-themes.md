## Intent

From any screen the reader taps a **palette** icon in the top app bar. A small menu opens with
four colour swatches (Pitch Green, Stadium Blue, Trophy Gold, Guardian Red) and a
Light / Dark segmented control. Picking one recolours the whole app instantly. Default
is Stadium Blue, in light or dark matching the device on first visit (today's look); after that only the reader's choice counts.

## Data reality

No API involvement. The "data" is the colour scheme generation, checked for real:

| Spec asks | Generator gives | Mockup does |
|---|---|---|
| 4 seeds × light/dark | `@material/material-color-utilities` 0.3.0 generates all 8 schemes | Inlines the 8 generated token sets |
| Theme should "look like" its seed | `SchemeTonalSpot` (MD3 default) mutes seeds: Guardian Red → `#904a44`, Pitch Green → `#3c6939` | **Proposal: `SchemeFidelity`**, primary stays close to seed (red `#a20513`, green `#0d631b`, gold `#785600`, blue `#004d99`). See Q1 |
| Current shipped Stadium Blue | `app/theme/tokens.css` primary `#2b5ea7` (hand-copied, matches neither variant exactly) | Blue light becomes Fidelity `#004d99`, a visible change to the default. See Q1 |
| Article body / images | Guardian HTML, photos | Untouched; only the 18 `--md-sys-color-*` roles in tokens.css change |

Derived values:
- `theme ∈ green|blue|gold|red`, default `blue`; anything else → `blue`.
- `mode ∈ light|dark`. No "System" option. With no stored choice, mode is taken once from `prefers-color-scheme`; once picked it no longer follows the OS. Unknown value → that same OS-derived default.
- Applied as `<html data-theme="…" data-mode="light|dark">`; tokens.css holds 8 blocks
  `[data-theme=x][data-mode=y]{…}` generated by a script (`scripts/gen-themes.mjs`), not hand-edited.

## States

- **First paint:** server reads the stored choice and sets `data-theme`/`data-mode` on `<html>` so there is no flash (needs storage, see Q2). With nothing stored, a `prefers-color-scheme` media query picks the mode, so no JS is needed.
- **Storage unavailable / unknown value:** falls back to Stadium Blue in the device's light/dark mode.
- **Loading / empty / error panels:** themed like everything else; button still available.
- **Failure of this feature** (bad token block, JS error in menu) leaves the default tokens in place, list/article/back flow unaffected.

## Open questions

Approved 2026-10-12 with every proposal below accepted as written.

1. **Scheme variant:** `SchemeFidelity` (proposal: seed-true, vivid red/green; slightly changes today's blue) or `SchemeTonalSpot` (MD3 default, softer, all four look muted)?
2. **Persistence:** backlog #4 is "persist view + theme". Proposal: store theme in a cookie now (`sr-theme`, `sr-mode`), same as `sr-view`, since without it every reload resets and flashes. Or keep this build session-only and leave it to #4?
3. **Placement:** palette icon in the top bar (proposal) vs. an overflow `more_vert` menu with "Theme…" (keeps bar to 2 icons on phones)?
4. **Swatch colour:** show the raw seed (proposal, recognisable) or the scheme's `primary` for the current mode?
