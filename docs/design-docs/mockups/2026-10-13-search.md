## Intent

A search icon in the top app bar opens a search screen (`/search`) with an MD3 search field in
place of the bar. The reader types a word ("tennis", "Ashes", a player) and presses Enter; the
headline cards for matching Guardian sport stories appear, newest first, with a result count.
Tapping a card opens the existing article screen; Back returns to the same results. The query
lives in the URL (`/search?q=tennis`) so refresh, Back and sharing work.

## Data reality

| Reference / intent has | Data has (live 2026-10-13) | Mockup does |
|---|---|---|
| Search "sport news" | `section=sport` excludes football: `salah` → **6** hits; `section=football` alone → 3,880; `sport\|football` → 3,972 | Proposal: search `sport\|football` (Q1) |
| Match results | `q` matches headline **and body**; `tennis` → 17,734. With `order-by=newest` the top hit is a quiz that mentions tennis | Newest first (proposal), relevance as alternative (Q2) |
| Relevance option | `order-by=relevance` works | Not drawn (Q2) |
| No match | `zzqxv` → `total: 0`, `results: []` | No-results panel |
| Operators | `"world cup" AND final` works (1,494) | Passed through as typed; not advertised |
| Highlight of matched words | No highlight field in the API | Proposal: bold exact case-insensitive matches in the headline client-side (Q4) |
| Suggestions / autocomplete | None in the API | Static "Try" chips (proposal, Q3); no autocomplete |
| Count | `response.total` | "17,734 results for “tennis”" |

Endpoint: `GET /api/search?q=Q&page=N` → `searchSport(q, page)` calls `/search` with the same
`show-fields` and page size (20) as `fetchSportPage`, plus `q` and `section=sport|football`.
Server page `/search?q=` calls `searchSport` directly for page 1.

Derived values:
- `q` = `searchParams.q`, trimmed, max 100 chars; empty → screen 2 (no API call).
- Count text = `total.toLocaleString("en-GB")` + ` results for “q” · newest first`; `1 result` singular.
- Live badge rule unchanged (`type === "liveblog"`).
- Highlight: split `q` on whitespace, drop operators (`AND OR NOT`) and quotes, wrap whole-word matches in the headline in `<mark>` (bold, no colour). Trail text is not highlighted.

Fields left out: `type` filter on search (could reuse the content-type chips later, Q5).

## States

- **Loading (submit):** search bar stays, count line + cards → skeletons.
- **Empty query:** screen 2, no API call.
- **No results:** screen 4.
- **Error / rate-limited:** existing `ErrorPanel` below the search bar; Retry keeps `q`.
- **Query too long:** cut to 100 chars silently.
- **Not applicable:** article screen has no search icon. A search failure only affects `/search`; the home list is untouched.
