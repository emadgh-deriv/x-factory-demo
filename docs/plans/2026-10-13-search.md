## Risks
- `md-assist-chip` is new to the app; registration in `MdLoader`.
- Search uses `sport|football` while home is `sport` only (Q1 proposal) — results include football the home list never shows.
- 500/day key: Enter-only submit, `revalidate: 60` cache.

## Proof
- Unit: `lib/search.test.ts`, `searchSport` in `lib/guardian.test.ts`.
- Browser: real queries "tennis", "zzqxv", empty; Load more; article → Back; 3 viewports; forced error.

## Departures from the mockup
- Bar order on list screens is Search · View · Theme. The mockup frame draws Search · Theme · View, but the shipped bar already had View before Theme; only the search icon was added (first, as specified).
- Autofocus only when the screen opens with an empty query (and after Clear). Autofocusing on a results page would pop the phone keyboard on every Back from an article.
- Open questions 1–6 were not answered in the approved pair; all proposals were built (see top).

## Not verified
- Slow-network throttling (no throttle control in the pane); the loading skeleton was observed on the real network.
- Real 429 rate-limit response (only 401 via an invalid key); both use the same `ErrorPanel` path, and `searchSport` mapping 429 to `rate-limited` is unit-tested.
